LangX — A Programming Language That Blends English with Symbols
──────────────────────────────────────────────

LangX is a programming language, built entirely in Rust,  
designed to interpret **structured English combined with mathematical symbols** as real, executable code.

This is not a chatbot.  
Not an AI agent.  
Not a natural-language interface duct-taped to Python.  

LangX is a **real language** — with grammar, syntax, and a runtime — where clarity meets precision.

───────────────
🛠 Purpose
───────────────
LangX exists to answer one question:  
**Can we create a language that's as clear as English but as precise as traditional programming?**

This project aims to:
- Combine English clarity with symbolic precision
- Define grammar strictly using parser generators (LALRPOP)
- Interpret and run statements deterministically
- Eliminate ambiguity through smart syntax design

───────────────
🧠 What It Is (and Isn't)
───────────────
✔ A real programming language with hybrid syntax  
✔ Built in Rust, with real tools: `logos` for lexing, `lalrpop` for parsing  
✔ Executes statements with English keywords and mathematical operators  
✔ Structured and formal — not freeform, not conversational  

✘ Not dependent on LLMs or AI at runtime  
✘ Not fuzzy or probabilistic — deterministic behavior only  
✘ Not just a transpiler — LangX has its own runtime and execution engine

───────────────
🔧 Architecture
───────────────
1. **Lexical Analysis** — Tokenize English keywords and symbols  
2. **Parsing** — Convert token stream into an Abstract Syntax Tree (AST)  
3. **Interpreter** — Walk the AST and execute commands directly  
4. **Runtime** — Manage memory, variables, scopes, and control flow  
5. **CLI / Runner** — Execute `.lx` files or run interactive REPL

───────────────
🚫 No AI During Execution
───────────────
LangX may be developed with AI assistance (editing, suggestions, architecture),  
but at **runtime**, no inference, no models, no guesswork are allowed.

The language must:
- Be fully defined by human-written grammar rules
- Execute based on internal logic, not LLM prediction
- Be inspectable and debuggable at every level

───────────────
📐 Syntax Example (LangX)
───────────────

# Variables and arithmetic
Set x to 10 + 5.
Set y to x * 2.

# Logic with words
Set flag to true and false.

# Conditionals
If x is greater than y then print "x is larger".

# Functions
Define add with parameters a, b:
    Return a + b.
End definition.

Set result to Call add with 5, 10.
print result.

# Loops
Repeat 3 times: print "Hello".


───────────────
✨ Syntax Design Philosophy
───────────────
LangX uses a **hybrid approach** that solved the classic parser ambiguity:

• **Arithmetic**: Mathematical symbols (+ - * /)
  - Universal, precise, unambiguous
  - Example: `Set x to 5 + 3 * 2.`

• **Logic**: English words (and, or, not)
  - Clear intent, readable conditions
  - Example: `Set flag to a and b.`

• **Control Flow**: Natural language
  - If...then, Repeat...times, Define...End
  - Example: `If x > 5 then print "yes".`

• **Function Calls**: Commas separate arguments
  - Example: `Call add with 5, 10`
  - Parentheses for complex expressions: `Call func with (a and b), (x or y)`

This design eliminates ambiguity while keeping code readable and maintainable.
